# A3 canary worker — 0003

Use only after the operator authorizes a G7 canary batch and gives its exact
batch UUID and workspace root. This does not authorize formal emote-000 through
emote-120 tasks or a production classification run.

Your worker_id is **0003**; core/result agent_id is **emote-0003**.
A3 is a role label. The same OAuth owner's other conversations can impersonate
a logical worker; it is not an authentication credential. Access/OAuth and the
server batch/tool allowlist still apply.

1. coord_claim_next: worker_id="0003", authorized batch_id, fresh UUID
   request_id, lease_seconds<=600. Keep only this claim's task ID, attempt_no,
   lease_token and lease_until.
2. Inspect the task and read assigned task/refs files. Canary data is explicitly
   synthetic. Preserve schema, reference evidence, image coverage and uncertainty
   notes when applicable; do not guess identities for synthetic inputs. Inputs
   and refs are read-only.
3. Scratch path: workers/0003/attempts/<task-id>/<attempt-no>/ under the
   authorized workspace. Set result.agent_id="emote-0003" and current
   attempt_no. Never write results/ yourself; the trusted native action publishes.
4. After concrete work call coord_report_progress with worker_id, batch_id,
   exact ID/token/attempt, next sequence, fresh request_id and a short checkpoint.
   If more time is needed while active, coord_extend_lease_progress consumes that
   fresh sequence. Each lease<=600s, attempt budget<=3600s, execution attempts<=3.
5. Validate result, then coord_submit_result with worker_id, batch_id, exact
   ID/token, result and fresh request_id. A validator may return submitted:
   accepted is not yet a verdict. On confirmed submission immediately claim next.
6. On empty, coord_agent_status(worker_id,batch_id). Inspect batch_progress.status,
   active and states. Empty/active_claims=0 does not prove completion. Leased,
   submitted or backoff tasks can remain. Cancelled stops work; completed with
   failures/cancellations is not all-success. If waiting, report the snapshot and
   stop the turn; a user may need to resume it.

On definite failure with a valid lease, coord_report_failure carries the same
worker/batch/token and bounded error. On lost/expired lease stop this attempt;
do not renew, submit, publish or fetch another worker's token. Uncertain writes
are never replayed automatically: inspect exact task/attempt/status first.
Do not log tokens or put them in results/shared files. No page, socket or old
checkpoint proves liveness; without active progress allow expiry and recovery.
ChatGPT background wake and 24-hour autonomous work are not promised.
